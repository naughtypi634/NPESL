# Anti-AI slop（审已有界面）

上游 Hallmark 是「生成新页面」用的，明确写了不要拿它重做已有设计。这里只用它的判据做
**审**：找出生成感的来源，只改真正是 tell 的那几处，不推翻站点自己的排印和配色系统。

## 生成感从哪里来（按命中率排）

1. **眉标（eyebrow）**：标题上方一行 10–11px、大写、加字距、等宽或 mono 的小标签。
2. **中点连接的元信息**：`Design · Dev · Ops`、`城市 · 单位 · 指标` 这种一串。
3. **小写标签用大写小字距**：表头、标签、导航链接。
4. **浮岛导航**：底部悬浮、毛玻璃、圆角胶囊、图标加文字，盖在内容上。
5. **KPI 墙**：一排大数字 + 小标签 + 彩色涨跌，数据本身撑不起这么多图。
6. **卡片汤**：所有东西都装进 1px 边框 + 大圆角的卡，卡里再套卡。
7. **紫蓝渐变、emoji 当图标、手绘浏览器窗口、装饰性状态点。**
8. **仪表盘模板骨架**：标题 + 副标题 + 大数字右上角 + 卡片 + 侧栏，换成任何产品都成立。
9. **解释性小字**：右下角一行灰色小字，替界面解释它自己没表达清楚的操作。
10. **动效没有职责**：进场动画、逐个延迟、悬停抬升，删掉不损失任何信息。

## 图表额外几条

- 一个值用 stat tile，不要画一根柱子的图。
- 部分与整体用堆叠条，不用饼图；超过七个分类用表格。
- 柱宽 ≤24px，只圆数据端；网格线 1px 实线，3–5 条。
- 折线 2px，标记只出现在有标注的点。
- **不做双轴**（拿来伪造相关性的经典手法）；不同单位用两张小图。
- 颜色用同一色相的明度梯度，文字不要穿数据的颜色，数字用等宽数位。

## 怎么审

1. 先看渲染结果（截图，桌面 + 手机 + 深色），再看源码。
2. 每条 tell 记「位置 + 为什么像生成的 + 替代方案」，不要只记「不好看」。
3. **分两类**：站点自己的风格系统（排印、配色、导航形态）不动；真正多余的装饰才改。
4. 判断标准不是「够不够酷」，是**这段东西有没有职责**：删掉它，信息有没有损失。
5. 已经有理由的例外要写出来（例如双轴正是这门课要教的图表本身）。

## 输出

先一句结论（像设计的 / 有几处 tell），再列 `file:line`，每条给替代方案。
